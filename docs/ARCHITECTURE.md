# Architecture

## The three-tier system

Throttle.toys is split across three independent layers, each in its own home:

```
┌──────────────────────────────────────────────────────────────────────┐
│  1. STATIC FRONT-END (this repo)                                      │
│     github.com/throttletoys/throttle-site                             │
│     → deploys via FTPS to cPanel /home/throfoxv/public_html/          │
│     → served by LiteSpeed/Apache at throttle.toys                     │
│                                                                       │
│  2. API SERVER (separate, not yet on GitHub)                          │
│     cPanel Node.js app at /home/throfoxv/nodeapps/throttle-api/       │
│     → Node.js 20, Express-style, MySQL via mysql2                     │
│     → served at api.throttle.toys                                     │
│     → /api/listings, /api/ingest, /api/trends, etc.                   │
│                                                                       │
│  3. SCRAPER PIPELINE (separate repo)                                  │
│     github.com/throttletoys/throttle-scrapers                         │
│     → runs in GitHub Actions on a cron                                │
│     → discovers OEM dealers, scrapes inventory, POSTs to /api/ingest  │
└──────────────────────────────────────────────────────────────────────┘
```

Each tier can be updated independently. The front-end never touches the DB directly — everything goes through the API.

```

│

```

## Deploy mechanics

### How a push to main becomes a live change

```
You: git push origin main
            │
            ▼
┌───────────────────────────┐
│ GitHub receives push       │
└───────────┬───────────────┘
            │
            ▼
┌───────────────────────────┐
│ .github/workflows/         │
│   deploy.yml triggered     │
│   (push event, main branch)│
└───────────┬───────────────┘
            │
            ▼
┌───────────────────────────┐
│ Job steps:                 │
│  1. actions/checkout@v4    │
│  2. FTPS connect to        │
│     server395.web-hosting  │
│  3. Diff local vs remote   │
│  4. Upload changed files   │
│     to /public_html/       │
│  5. Skip excluded paths    │
│     (.git, .github, docs)  │
└───────────┬───────────────┘
            │
            ▼
┌───────────────────────────┐
│ LiteSpeed serves new files│
│ Cloudflare cache purges*  │
└───────────┬───────────────┘
            │
            ▼
   throttle.toys is live
```

**Total time:** ~60–90s from push to live.

\* Cloudflare auto-purges based on filename+modified-time. If you change `assets/main.css` you may need to also bump a query string (`?v=2`) for browsers to refetch.

### Files that are NEVER touched by deploy

The deploy workflow uses `state-name: .ftp-deploy-sync-state.json` and `exclude:` rules so the following stay untouched on the server:

| Server file | Why kept |
|---|---|
| `error_log`, `*.log` | Apache-generated, must not be uploaded |
| `_audit.php`, `_b.php`, etc. | Debug endpoints — not in repo |
| `nc_assets/fonts/*` | Legacy webfonts from previous host |
| `throttle-everything/` | Admin tooling, backups |
| `cgi-bin/` | cPanel-managed |
| `.well-known/` | Let's Encrypt + others |

If you delete a file from the repo, **it does NOT get deleted from the server** unless you use the `dangerous-clean-slate: true` option (we don't, intentionally). To remove a file from the live site, log into cPanel and delete it via File Manager.

## Preview deploys (PR previews)

When you open a PR, `.github/workflows/preview.yml` deploys your branch to:

```
https://throttle.toys/preview/<PR-number>/
```

This lets reviewers see your change as a real, hosted preview before merging.

Preview deploys are cleaned up by a separate workflow when the PR is closed.

## Local development → production

Going from `localhost:8000` to `throttle.toys` has one gotcha:

**The API is at `api.throttle.toys`**, not `localhost`. The site's JS hits the real API even when you're developing locally. That means:

- ✅ You see real listings, real categories, real photos
- ✅ No need to run the API locally
- ⚠️  Any "list a toy" form will hit production (use the `?dry=1` query param to skip submit)
- ⚠️  Auth doesn't work from `localhost` — log in on production, then use that cookie

## DNS + TLS

- **Domain:** `throttle.toys` registered at Namecheap
- **DNS:** Cloudflare (proxied A record → cPanel IP)
- **TLS:** Cloudflare Universal SSL (origin) + cPanel AutoSSL (Let's Encrypt fallback)

Cert renewals are fully automated. There's no certificate you need to touch.

## Dependencies & versioning

This repo has zero runtime dependencies. Everything in the browser is either:
- Plain HTML/CSS/JS (no transpile)
- CDN-loaded library (Leaflet, Chart.js, Tailwind preflight)

Dev dependencies (htmlhint, stylelint, vite for local serve) are in `package.json` and locked via `package-lock.json`. Dependabot auto-PRs updates weekly.

## Why not [framework]?

We're a 1–3 person team shipping marketing+marketplace HTML. The cost of "set up React, set up TypeScript, set up bundler, hire someone who knows that stack" is far higher than the cost of writing vanilla HTML and editing it directly. When we have 100+ pages and complex state, we'll re-evaluate.

## What's NOT in this repo (by design)

| Thing | Where it lives | Why separate |
|---|---|---|
| Node.js API source | cPanel `/home/throfoxv/nodeapps/` | Different deploy lifecycle, lives on the server |
| Scraper pipeline | `throttletoys/throttle-scrapers` | Different audience (engineers), different cadence |
| DB schema | cPanel phpMyAdmin + scraper repo `schema.sql` | Schema changes are infrequent + risky |
| Admin debug scripts | cPanel server-only | Should never be publicly indexed |
